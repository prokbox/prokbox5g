# Upstream backport candidates (the single list)

*Started 2026-10-24 at the owner's request: "Keep everything that could go back upstream in a list."*

**Purpose.** This is the one place that records everything in this tree that could go back to upstream Rockbox: bug fixes, corrections, build and simulator fixes, hardware knowledge, performance work and features. **Plan (owner):** once the full release is stable and feature-complete, the owner audits this list and backports improvements, corrections and fixes to upstream. **When (owner, 2026-10-26): once ProkBox5g is stable at 1.2**, the backport work to upstream Rockbox begins. Nothing here is sent yet.

**Rule.** Every phase close (and every ledger update, `docs/process.md` step 7a) appends its new upstream candidates here, in the right group, with all columns filled. Remove nothing; change the status instead (`sent`, `merged upstream`, `dropped: reason`). Upstream's philosophy is broad-target, so the "generic or specific" column says what must be un-specialised (our `HAVE_IPOD_UI`/`UI_COMMIT` guards, flash-vs-HDD assumptions, one-target tuning) before a patch can go. The full diff stays in `docs/changes-from-rockbox.md` (§4 is the older, shorter list; this file supersedes it for planning).

**Columns.** Item / upstream files / where it lives (commit, branch or ledger section) / generic-or-specific (what to un-specialise) / status (`ready`, `needs generalising`, `planned`, `idea`) / notes. Commits are on `main` unless a branch is named. Hashes marked "ledger" are not looked up yet; the ledger section has the detail.

## 8. Not upstream (the audit can skip these)

- Everything under `apps/ipodui/`: the Apple-style shell, fonts (ShellSans), strings, artwork, module loader and games.
- Anything guarded by `HAVE_IPOD_UI`, `UI_COMMIT` or `IPODUI_*` that serves the shell: boot battery guard and latch, boot stamp and boot window, library generations, statistics journal, safe replaces and the rename intent record (our policy; the FAT ordering in section 1 is the generic part), panic record restart loop, paused-window playback (`audio_buffer_give`), sleep (P18) hooks, 3 s dark storage hold.
