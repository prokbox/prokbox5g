# 14. Quirks: where silicon differs from assumptions

Every entry is a place where the BCM2722 behaved differently from a reasonable assumption: VideoCore IV analogy, a reading of Apple's code, or our simulator before it was corrected. Each says what silicon does, what was assumed, and the session that showed it. If you are porting VideoCore IV knowledge, read this first.

Numbers are unique and permanent; the tables are grouped by topic, not in number order. (On 2026-10-26 the five clock-and-bus rows that had reused 16–20 were renumbered 42–46; every other reference to #16–#20 means the instruction-set and vector rows.)

## Simulator-only artefacts to avoid

These are properties of models (ours or others'), not of silicon, that misled at some point:

- A simulator that faults on misaligned accesses hides quirk #2.
- A simulator that silently accepts every misaligned access (vc2sim's vector and DMA models before strict mode) hides the opposite: quirks #17a, #18 and #34 turn a misalignment into wrong data with no fault. vc2sim's strict alignment mode (`memory-access.md` §11) traps what silicon has not shown.
- A host-port model that honours a write address to the halfword hides quirk #34.
- A model that decodes code from memory as it is, whenever it first runs, hides quirk #40: it runs code the core has just written as silicon may not. vc2sim's strict code coherence (`vc2sim.StaleCode`, on in every `hello_test.Bench`) takes memory as it stands at each cache flush (the host's or the core's bit 30) as what instruction fetches may read, and refuses a first fetch of bytes written since.
- A model that answers host-port reads by popping a FIFO per halfword splices bytes from different words [external: siggifly note 12, a retracted reading].
- The boot ROM's `0xE0000` buffer is a command-parameter area, not the panel: a host-side emulator that treats it as the screen draws the NOR firmware's logo unplaced [external: siggifly note 14].
- A job or FIFO model that lets the core see a host write the moment it is made hides quirk #47. `vbcm_model.c` (the host-test model of the chip) now refuses a `FEED` of bytes not yet behind a host read of them or 2 ms old (or 4 KB written after them); vc2sim's port model reproduces the late write the same way.
- A job model that offers an overlay's ops before the overlay is loaded hides quirk #49: the simulator's job model now takes its capabilities from what has been loaded (`sim-fidelity.md` §9a).
