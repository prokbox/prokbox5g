# Process: phase lifecycle, gates, agents

Adopted 2026-10-06 after auditing Phases 0–4. The goal is the **same or higher fidelity for less time and fewer tokens**. Problems are caught at the cheapest point: brief, then self-review, then gate, then end review. Expensive work is never repeated.

## Phase lifecycle

| Step | Who | Output | Cost note |
|---|---|---|---|
| 1. **Brief** | orchestrator | `docs/phaseN-brief.md`: goal, out of scope, **contracts**, file ownership, **device-reality checklist answers**, acceptance criteria | Contracts let agents work in parallel without waiting on each other |
| 2. **Brief review** | `budget-reviewer` (read-only, top model) | Approve, or list design risks **before any code exists** | Cheapest place to catch the kind of design bug Phase 4 needed two failed reviews to find |
| 3. **Fan-out** | specialist agents in **worktrees**, one owner per file | Commits on agent branches. Each agent hands back only after a **self-review** against the checklist below and a `validate.sh --quick` pass | Agents iterate with `--quick` plus their own scripts, never the full gate |
| 4. **Integrate** | orchestrator | Merge into `phaseN`. TEMP and DEV commits are dropped or reverted. **Full `scripts/validate.sh` runs once**, including the upstream dry-run | One full gate per integration |
| 5. **End review** | `budget-reviewer` | Confirms the brief review's points and checks for anything new. It should mostly *confirm*, not *discover* | If it discovers a High finding, record why the earlier steps missed it and fix the checklist |
| 6. **Owner round** | orchestrator → owner | **One batched** set of questions (decisions, golden approval, side-by-sides) | The "Decisions needed" list in `ROADMAP.md` collects them during the phase |
| 7. **Close** | orchestrator | Goldens committed, merged to `main`, pushed to `forge`, issues closed, budget table updated, worktrees removed | |
| 7a. **Ledgers** | orchestrator | At close, update `docs/changes-from-rockbox.md` (run `scripts/upstream_changes.sh`, and with a second ref for a pending branch) and `docs/design/changes-from-7g.md`; append upstream candidates to `docs/upstream-backports.md`. Every owner decision that moves a stock difference is recorded in the second ledger | Two small docs that stay true only if touched at every close |

Split phases by **risk**, not by feature. Core database, playback, storage or memory changes are their own mini-phase with their own review, ahead of the UI that uses them.

## Brief template (mandatory sections; the brief review rejects a brief without them). Adopted from process audit 2, 2026-10-07.
1. **Owner pre-flight done:** questions answered (see `docs/owner-questions.md`) and captures listed. Anything still open is frozen as ⚠️ **with a default** until the owner round, and the brief is not revised mid-phase for it.
2. **Read list per agent:** at most 3 files or sections, pointing at the **per-screen spec files** (`docs/design/spec/*.md`), never the whole spec.
3. **Contracts as real code** (lessons from the Phase 5 end review: keep identity separate from validity, e.g. a track id vs a table seqlock; and **name the trace macro**: shell trace lines use `UPDATE_TRACE`/`DEBUGF`, because `logf` is a no-op in `apps/ipodui`. A trace rule that finds none of its lines must fail, not "skip"): shared headers and file-format structs (`*.h`) are **committed to the phase branch before fan-out**, together with a round-trip host test and a single shared stub. Agents don't write their own TEMP stubs, and the gate refuses `TEMP-` commits.
4. **Ownership table, device-reality checklist answers, acceptance criteria, review videos and images.**
6. **Hardware features (required, owner 2026-10-24).** Name the blocks in `docs/hardware-features.md` that could carry this phase's work (PP5022 CPU/COP, BCM2722, WM8758, a cross-chip path), with the catalog row IDs. For each, state the CPU fallback, and for any row marked unknown or unverified, the probe that settles it and when it runs. "None apply" needs a one-line reason. The brief review rejects a brief without this section.
7. **State of the art (required, owner 2026-10-24).** Name the state-of-the-art algorithm for each hot path the phase touches (cite `docs/algorithms-survey.md`) and whether we adopt it. If not adopted, give the reason in one line (cost, cache, licence, no measured gain).
5. **Brief revisions are sent to running agents as deltas** (a SendMessage with only the change), not as re-reads.

## Agent budgets and fix rounds
- **Hand-back budget:** a specialist hands back by about **250k tokens**, or after **2 failed fix attempts** on the same failure, whichever comes first, reporting the state and the blocker.
- **Gate runs:** go through `scripts/gate-run`, which keeps one run per worktree under a lock, refuses a third `--quick` in one task, and defaults to `--quick --changed`.
- **Fix rounds** go to the **original agent**, resumed with SendMessage so its context is kept. The orchestrator does the mechanical merges itself.
- **Goldens:** agents only *propose* them. `scripts/golden_capture.sh` writes a golden only if two runs are pixel-identical. Time-varying sim state is pinned by default.

## Lean coding rules (from `docs/code-audit-1.md` §4, adopted 2026-10-07)
Every self-review and end review checks these. The reasons and measurements are in the audit.
1. No per-pixel `lcd_*` calls or divides in loops. Pre-render glyph tiles and anti-aliased edges once into a movable block, then blit them.
2. Gloss, gradients and overlays use precomputed per-row colour tables.
3. Never re-render text you just rendered. Repeated frames (marquee, overlays, cross-fades) blit from a buffer. Text costs about 30 instructions per cell pixel.
4. Redraw the changed rectangle, not the screen. A full-list redraw needs a written reason.
5. One timer source: every periodic wake goes through the main loop's timeout, with lit and dark rates stated in the brief. Pollers trigger on the producer's visible change (for example the commit sequence), not on intermediate progress.
6. Boost while composing, including a transition's first frame. Never boost while blocked on I/O.
7. Bulk moves use `memcpy`/`memmove`/`memset16`, never per-pixel C loops.
8. Per-frame code reports an instruction count from the ELF harness. Budget per 33 fps frame: about 300k instructions boosted, before the push.
9. Every new reservation names what it shares with (strip, background arena, panel transient). A new permanent block needs a line in the budget table and a "can't share because" sentence.
10. Count storage reads per user action. Probe loops become one range read or a RAM table.
11. **Bulk I/O, never streamed (owner, 2026-10-09).** Don't stream data into a buffer through many small reads. Read large contiguous chunks sized to the caller's buffer, touch each byte once, coalesce adjacent ranges, and pre-render or pre-compute at build or sync time so browsing reads one prepared blob. Report `read()` calls and bytes per action. The modded unit's big battery is no excuse: builds for stock-battery 5G/5.5G units are planned. (Found when one uncached 1,100-chapter m4b took about 3,170 reads to open.)
12. **Alignment (owner, 2026-10-25).** The PP5022 data-aborts on a misaligned halfword or word load or store (`docs/pp5022-reference/quirks.md` #51); the macOS sim and host tests accept it silently. A block handed out of a buffer, a record in a file image, a table after a header: every `uint16_t`/`uint32_t`/struct view of it sits at a multiple of its size (a layout constant, an aligned allocation, `SDK_REC_OFF`-style padding), or is read and written with `memcpy`. Enforced three ways, all hard failures: (a) `scripts/risk/sim_ubsan.sh` builds the sim with `-fno-sanitize-recover=alignment` and any misaligned access in `apps/ipodui/`, the iPod target, `firmware/common` or `bcmfw` fails the full gate (`STRICT:`, exit 3); (b) `scripts/test.sh` puts `scripts/align-shim` first on `PATH`, so every host test built with `cc`/`gcc`/`gcc-16` aborts on a misaligned access (`ALIGN_SHIM=0` to compare; `ALIGN_SHIM_ALLOW=1` for a deliberate one, with a comment why); (c) `tests/aligncast` fails when a file gains a byte-offset cast to a 16/32-bit pointer, `(uint32_t *)(buf + off)`, beyond `tests/aligncast/baseline.txt`; review the new site and mark it `align-ok: <why>` in a comment on its line, or use `memcpy`. A host stub that models chip or device memory must use `memcpy` too (a host-port word at a 2-mod-4 chip address is legal; the stub's cast was not). A misaligned-by-construction test shim is a bug: `tests/fatcrash/shim/config.h` once left `UNICODE32` off, which sent `fat.c` through a `uint16_t *` into `ucschar_t *`.

## Device-reality checklist
Every brief answers each line, and every self-review and end review checks it. The simulator differs from the iPod in all of these ways:

1. **Compiled features:** `HAVE_DIRCACHE` and other target-only defines. Which code path runs on the device? Is it tested?
2. **Memory:** any `core_alloc` or `core_alloc_maximum` while audio plays makes playback shrink the buffer, which means a gap or a stop. Defer the allocation, or use the existing pools. **Check, then allocate, with no yield in between:** an `audio_status()` check followed by file I/O and then `core_alloc` is a race. Re-check immediately before the allocation. Also say how the freed space gets back to the audio buffer (a block allocated while stopped shrinks the buffer, and nothing re-grows it until a rebuild). (Lesson from the H1 end review.) **Indirect allocations count too:** `lib_open()` (view pool), tagcache searches with RAM cache growth, font or skin loads. A panel or draw callback must never call them; precompute the value instead. (Lesson from the #38 end review: the podcast count.)
3. **CPU:** the device is about 400× slower than the sim (uncalibrated). Any O(N) work over 50k entries on the UI thread needs a device estimate and yields.
4. **Storage:** every disk walk, lookup or changelog pass wakes the flash and costs battery. Count them per user action. **Model real timing:** after a buffer fill, `storage_sleep()` puts the disk to sleep about 200 ms later, and *paused* reads as playing. Any simulator stand-in for a device signal (disk active, battery, USB) must reproduce the device's timing, or the test passes when the device would fail. (Lesson from the Phase 4b-1 review: the art builder could never run during playback.)
5. **LCD:** pushes go over the BCM bridge. Use full-width bands only, and give a frame budget for each animation.
6. **Threads and locks:** the tagcache thread, the audio thread and the UI thread. Look for mutexes taken from the UI, and pointers held across anything that yields.
7. **Upstream splashes and prompts** reachable from any shell path.
8. **Persistence:** what survives a rebuild, a power-off mid-operation, or a USB connect mid-operation? For each persistence trigger, name the executing thread and call path, and give one script per trigger in the user's real state (playing). (Lesson from the P6 end review H1: the stop record waited for a UI pass that a power-off never runs.)
9. **Scale:** the cost at 50k tracks and 5k albums, measured in the sim with `tests/perf/lib50k.sh` and estimated for the device.
10. **Deferred or retried work:** for every operation that waits for something (playback stopping, USB, the next boot), list each database state it can be retried in (*ready*, *fresh or rebuilding*, *dirty*) and give each one a test script. Added after review H1 in Phase 4: a retry guard was only tested in the *ready* state. **Say what the user sees in each state, not just whether the retry happens** (lesson from the 8b brief review H1: removing a status row left lists empty and unexplained during the commit window).
11. **Stock firmware unchanged:** stock `.text` is byte-identical to `build/fw/.size-baseline`. **One accepted exception (2026-10-08):** new shell strings in `apps/lang/english.lang` (rule 8, localisation). They are scoped to the `ipodui` feature and **appended at the end**, so existing IDs keep their numbers, but the phrase count still changes a few stock objects. Verify identity with `english.lang` held equal (main's sources plus the branch's `english.lang` must cmp-match the branch), and treat any other difference as a failure.
12. **Existing upstream paths doing the same job:** list every upstream path that already does what the new code does (e.g. playback's audiobook autoresume vs a new resume store), and say which one wins and how the other is disabled. (Lesson from the P6 brief review.) **Include the shell's own existing handlers** (e.g. 8a's charging sleep in `ui_main.c`, not just upstream's `charging_splash()`), and say whether an upstream engine keeps references into any file we rewrite (the playlist engine keeps seek offsets into its playlist file). (Lesson from the P11 brief review.) **List every writer into a surface (e.g. every `xfade_rect` caller), not just the main path** (lesson from the 8b brief review H2: the drift's cover fade bypassed the compose path). **When code takes over a hardware path while the kernel is frozen (sleep, a boot window), list every driver state the normal path keeps for it** (e.g. the click-wheel controller powered off under Hold and re-initialised only by the button driver; lesson from the P18 brief review H1/H2).
13. **Builder iteration predicate:** for any work done by a background builder, name the exact predicate that selects items, and check it covers every case (e.g. coverless and multi-file books). (Lesson from the P6 brief review.) **Name every writer of the field a rule ranks by (e.g. the stamp's writers, including migrations)** (lesson from the 8b brief review H3: migration seeds were stamped in walk order).

14. **Hardware blocks considered:** the brief's "Hardware features" section is answered. Each catalog block used has a measured A/B against the CPU path (or a scheduled probe), the CPU fallback still works, and any new silicon finding is written into `docs/hardware-features.md` and the owning manual with its evidence tag.

Items that can't be verified in the sim go into **`docs/ROADMAP.md` → Device checklist (P10)** with a concrete test procedure.

## Agent self-review (before handing back)
- [ ] Every checklist item that applies to my change is answered in my report.
- [ ] `scripts/validate.sh --quick` passes, plus the scripts and host tests for my area.
- [ ] No new warnings, no splash, no "Rockbox" string, no static over 1 KB, `cpu_boost` balanced.
- [ ] Shared files I don't own are untouched (see the brief's ownership table).
- [ ] The report gives measurements (sizes, timings), not adjectives, and lists anything that needs a device check.
- [ ] **One gate at a time per worktree.** Before starting `validate.sh`, check that none is already running (`pgrep -f validate.sh` plus your worktree path; note that `validate.sh` runs each build and each UI-script worker in its own `$(...)`/`&` subshell — normal now that builds and UI scripts run in parallel — which `ps` shows as *more copies of* `validate.sh`, not a second gate. A real duplicate has its **own** parent shell and start time, so compare PPIDs before concluding anything). Wait for the single completion; never poll it in a loop or start a second. After a failure, re-run only the failing script or test.
- [ ] **Deterministic screenshots:** every time-varying piece of simulator state that appears on screen (clock, battery level, charging, anything animated) is pinned in scripted runs. A golden must be pixel-identical on two consecutive runs before it's committed. (Lesson: the battery fill drifted 1 px in long scripts.)
- [ ] **Hand back once.** No interim status messages, and no repeat full-gate re-runs after a passing `--quick` (the orchestrator's integration gate covers it). Never run `scripts/test.sh` concurrently with `validate.sh` in the same worktree; they share `build/warble`.
- [ ] Claims about other branches' state (for example "goldens unaffected") are stated as **"on my branch"**. The orchestrator verifies them at integration.

## Shared-file ownership
These files caused merge conflicts in Phases 3 and 4. Each brief names **one** owner per phase:
- **Test tooling:** `uisimulator/common/sim_script.c`, `sim_db.*`, `scripts/shots.sh`, `scripts/check_trace.py`, `tests/ui/README.md`. Owned by the verification agent; others ask via the orchestrator. New sim commands get their own `sim_cmd_*.c` file where practical.
- **`docs/hardware.md` budget table:** the **orchestrator** updates it at close. Agents report their numbers instead of editing it.
- **`apps/SOURCES`:** additions only, inside the existing `#ifdef HAVE_IPOD_UI` block. The orchestrator merges.

## Model tiers (fidelity first)
| Work | Model | Why |
|---|---|---|
| Briefs, contracts, reviews, core C (tagcache, playback, storage, memory), **visual-fidelity judgment** (comparing against 7G references, glyph and gloss design) | top (opus) | Mistakes here are expensive, and visual matching depends on judgment |
| UI implementation against a precise brief and existing visual contracts; test tooling, scripts, merges, doc integration; transcribing photos | `sonnet` | Its output is checked mechanically by the gate, goldens and review |
| Formatting, renames, index tables, mechanical edits | `haiku` | Fully verifiable, low judgment |

When in doubt, use the higher tier. Fidelity beats token savings.

## Gate (`scripts/validate.sh`)
- **Run it through `scripts/gate-run`**, not `validate.sh` directly (see "Agent budgets and fix rounds" above): one lock per worktree, at most two `--quick` runs per task (a third refuses; `GATE_FORCE=1` overrides it for the orchestrator), `--quick --changed` with no args, `--full` for the plain full gate. The orchestrator's own integration gate may call `validate.sh` directly.
- `--quick` while iterating: builds `fw-ui` and `sim-ui` only, plus host tests and the new-UI scripts. Stock `fw` is built only when a file outside `apps/ipodui/`, `art/`, `tests/`, `docs/` or `scripts/` changed (it proves guarded upstream edits keep stock byte-identical); `boot` only when `bootloader/` or `firmware/` changed; the stock `sim` and its smoke scripts only in the full gate. Every skipped build prints a `skip build ...` line with the reason. No merge-base with `main` builds `fw` too (cannot tell what changed). The full gate builds everything, unchanged.
- Full, once per integration: all builds, all scripts, goldens, trace rules, size, string check, and the **upstream dry-run** (`git merge-tree` against `upstream/master`). Conflicts are reported; the sync itself happens when it's cheap. The plain full gate (no flags) always covers everything below, regardless of `--changed`.
- **Parallel, same coverage.** Builds (`fw-ui`/`fw`/`sim-ui`[/`sim`/`boot`]) run concurrently, to completion, before any UI worker starts (`JOBS` make -j per dir, default ncpu+2 split across the builds, min 2 each; `JOBS=N` overrides). `tests/ui/*.script` run with `GATE_JOBS` parallel workers (default `min(16, 2*ncpu, mem GiB)`, i.e. 8 on the 8 GB dev Mac: the sims are wall-clock bound on scripted `wait`s, not CPU bound, so the knee is well above ncpu; `GATE_JOBS=N` turns it down); each script gets a fresh clone of the primed simdisk (`cp -c` on APFS), so a `fresh-db`/`rebuild_db`/`reboot` script only ever mutates its own copy. The shared disk (music/test library, built database) is primed **once**, serially, before any worker starts — no worker rebuilds it. `scripts/pngdiff.py --batch` diffs a whole script's goldens in one process. Results print in one block, sorted by name, not completion order.
- **One gate per machine.** `validate.sh` and `golden_capture.sh` take a machine-wide lock (`~/.cache/rockbox-gate.lock`, `simpool_machine_lock` in `scripts/simpool.sh`); a second gate or capture from any worktree prints `waiting for gate lock` and waits. Each one already sizes its pool to the whole machine, so parallelism goes into one pool, never into several agents' gates at once. (2026-10-09: two integrators each running 5 builds at -j4 plus 16 sims, with a VM up, exhausted the 8 GB Mac and it had to be force-reset.) Sims also play through `SDL_AUDIODRIVER=dummy` (shots.sh default): position follows the wall clock, not a loaded coreaudiod; scripts that check position wait with `wait_pos`, not `wait`.
- **Gate watchdog.** Waiters print the lock holder and how long it has held the lock. A gate or capture that runs longer than `GATE_MAX_MINUTES` (default 75) is aborted: its process tree is stopped, the lock is released and the log says `gate watchdog`. Agents must never hand back with a gate or capture still running in the background; stop it first. (2026-10-09: a finished agent's gate held the lock for 2 h while the integration gate queued.)
- **Flake guard.** A script that fails under parallel workers is re-run alone, serially, once the parallel phase ends (worker contention can make a sim flakier than running alone). `flaky-retry ok` if the retry passes; a real `FAIL` only if it fails alone too. The retry count is printed — repeated flakiness is a smell, not something to shrug off.
- **Deterministic resume state.** `scripts/shots.sh` clears `.rockbox/.resume.cfg` before every script's first boot (`# resume: keep`/`# resume: playing` opt out; see `tests/ui/README.md`), so a script's "Now Playing" visibility never depends on what ran before it on the same disk — required once scripts can land on a freshly cloned disk in any order, not just the old fixed serial sequence.
- **`--quick --changed`** (opt-in): narrows the `ipodui-*` selection to what `scripts/gate_map.txt` (path globs → script-name patterns) maps the files changed since `main` to. Anything unmapped, or a file the map marks `ALL` (shared UI infrastructure, tagcache), still runs every `ipodui-*` script — an unmapped file is an unknown risk, not a free pass.
- **UBSan pass.** Full gate: every `ipodui-*` script against `build/sim-ui-ubsan`, in `UBSAN_JOBS` (default `GATE_JOBS`) parallel workers on cloned primed disks, then the host tests. `--quick --changed` (narrowed by `gate_map.txt`): only the mapped scripts, the same list the UI pass just ran; plain `--quick` or a fall-back-to-all selection skips it. `GATE_UBSAN=0` skips it anywhere. Still a report, except misalignment: a misaligned access in the shell, target or bcmfw code is a `STRICT:` failure of the gate (item 12 of the lean coding rules); the sim is built with `-fno-sanitize-recover=alignment`.
- **Failure summary.** When a script really fails, the gate ends the UI results with a one-page summary: failing scripts with their first `FAIL` line, and `[golden | actual | diff]` composites for every golden mismatch under `out/gate-report/` (`index.md` links them; `scripts/gate_report.py`). `golden_capture.sh` writes the same for a refused capture (`[run1 | run-n | diff]`).
- **`shots.sh` watchdog.** Its timeout `sleep` must not inherit the caller's stdout: when it did, every `$(scripts/shots.sh ...)` in the gate waited the whole `SHOTS_TIMEOUT` (60 s) after the sim had already exited.
- **Golden capture is parallel too** (`scripts/golden_capture.sh a.script b.script ...`): the shared disk is primed once, then run 1, run 2 (and with `--verify3` a third independent run) of every script each go on their own `cp -c` clone, `JOBS` at a time (default `min(16, 2*ncpu)`). The rule is unchanged: pixel-identical at threshold 0 or nothing is written for that script. `--dry` compares without writing. Measured on this 8-core Mac: capturing 5 sets 784 s serial (old) -> 50 s; 28 sets x 2 runs at `JOBS` 4/6/8/10/12/16/24: 344/245/199/155/137/115/92 s, no refused or failed run at any count.
- **No TEMP- commits at the full gate.** `validate.sh` (full mode only) fails if any commit subject on this branch since `main` starts with `TEMP-` (`GATE_ALLOW_TEMP=1` overrides it for the orchestrator reconciling one on the way out) — see "Contracts as real code" above.
- **Shared, cached builds and simdisk.** Every build dir shares one `ccache` across every worktree (`tools/configure` wires it when `ccache` is installed). The primed simdisk (generated library/music plus the built database) is likewise cached by a hash of its generators and the tagcache/library/sortkey/artcache code, reused across worktrees from `$HOME/.cache/rockbox-simdisk` — a changed input is a cache miss, not a stale hit.

## Owner interaction
- Questions are collected in `ROADMAP.md` → **Decisions needed** and asked once per phase. The only exceptions are blockers.
- First-hand facts from the owner go straight into the spec, marked "(owner, date)", and override the guides.
- The 5.5G is off-limits until the owner says otherwise (see `CLAUDE.md`). A spare test unit is "maybe later".
