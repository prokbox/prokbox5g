# Cold-Thumb list (Phase 8b-T, docs/phase8b-brief.md section 4.T; #45).
#
# tools/root.make compiles exactly these sources with -mthumb when
# configure's --thumb-cold is on (the default for the shell firmware;
# --no-thumb-cold turns it off). One path per line, relative to the source
# root; no globs, so a file joins only by name. Everything else stays ARM.
#
# Rule for joining: the code runs on a press or once, never per frame,
# never in an interrupt and never in a bulk loop over the library or a
# file. A file that fails that rule joins only with a timing proof (< 5 %
# slower, the brief's T1b). Never Thumb: apps/ipodui/sortkey.c, codecs,
# plugins, firmware/, lib/, the hot list (library, list, paint, np_draw,
# artblur, artfmt, browse, nowplaying, search_core, buffering, playback,
# pcmbuf, tagcache). scripts/validate.sh prints this list with the size
# report.

# T1b (the timing-gated reserve): a file joins only with its proof.
# dbgen.c: runs once per boot (select) and per library update (prepare,
# publish). Its only loops over file bytes go one chunk (>= 1 KB scratch,
# DBGEN_SCRATCH_MIN) per pass, the bytes themselves through crc_32r() and
# read()/write() in firmware/ (ARM); its other loops cover at most 32
# manifest files (DBGEN_MAX_FILES). Thumb adds ~10-20 instructions per
# chunk against ~10k for the chunk's CRC: < 0.5 %.
apps/ipodui/dbgen.c
# chaincheck.c (p081-fatdb): dbgen's guard and read-backs, once per file
# per prepare; the chain walk itself is fat.c's (ARM), so Thumb adds a few
# instructions per file around it.
apps/chaincheck.c
# lib_shuffle_rec.c: seals and checks the shuffle record (a sum over its
# ~100 bytes) once per record write or boot check, each beside a file
# open/write/close; Thumb adds ~40 instructions per write: < 1 %.
apps/ipodui/lib_shuffle_rec.c

# frame, so Thumb adds at most ~400 against the 300k frame budget
